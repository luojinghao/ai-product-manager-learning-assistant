# 三个项目的落地指南

所有示例只使用合成数据，不调用外部模型或业务系统。先完成可复现基线，再在合法授权的场景扩大范围。每个项目建议按“问题—基线—方案—实验—用户验证—复盘”组织作品。

## 项目一：供应商知识库

运行 npm run project:knowledge，查看 examples/knowledge.js。脚本按组织与有效状态先过滤，再按关键词匹配候选，直接摘录最高分证据。输出五条题目的命中、拒答和来源。

1. 定义目标用户、任务与当前查资料用时。明确不替代合同审批或法律判断。
2. 用 10 份有授权脱敏制度，保留页码、章节、日期、组织、有效版本和负责人。
3. 手工建立至少 30 题：常见 10、长尾 5、无答案 5、过期冲突 5、越权 5。比例按实际风险调整，题目含标准证据和判定准则。
4. 先比较关键词基线，再加入 Embedding 和混合检索。拆分开发与独立测试样本，测 Recall@k、排序、权限和时效。
5. 若接 LLM，后端读取密钥并控制用量。给模型有限授权证据，输出带来源的回答。逐条检查核心断言是否被引用支持。
6. 测正确性、完整性、无答案拒答、引用支持、越权、P95 和成功任务成本。自动裁判需人工校准。
7. 让至少 3 位目标用户做真实但脱敏任务，记录总完成时间、复核时间、成功率与失败原因。

验收产物：访谈、数据授权清单、架构图、检索代码、黄金集、版本与评测报告、用户反馈和迭代决定。冒烟样例通过不等于生产验收。

## 项目二：需求预测与补货建议

运行 npm run project:forecast，查看 examples/forecast.js。前 12 周为初始训练，此后每周只使用过去数据预测下一周。比较上一期、4 周季节基线和线性回归；记录 MAE、RMSE 与单期成本近似。

1. 明确 SKU / 门店 / 时间粒度、预测窗口、交期与补货动作。区分销量与因断货未满足的需求。
2. 建字段字典，确认促销计划在预测时确实已知，历史字段不能被未来更新覆盖。
3. 用时间切分和滚动回测，预处理只在训练数据拟合。保留独立月份最终评估。
4. 对比简单基线、统计或树模型，需要时再用深度模型。分主力、长尾、促销、地区、新商品看误差。
5. 当前脚本成本是每个预测周期独立计缺货 8 元、剩余 2 元的简化，不含库存结转。真实仿真要补库存余额、交期、订货批量、产能、现金和退货。
6. 若做预测区间，用历史回测检查覆盖率；不能把区间宽度当业务安全承诺。
7. 先只输出人工审批建议，比较决策与现有策略，再在明确授权后试点。

验收产物：可重放数据快照、时间切分、泄漏检查、基线与候选回测、分层报告、库存仿真假设、人工反馈、监控和回退。

## 项目三：采购异常处理 Copilot

运行 npm run project:agent，查看 examples/agent.js。内存模拟订单可查询、生成催交草稿；未确认不发送；跨组织被拒；相同幂等键重试复用结果；同键不同内容报冲突。无真实邮件副作用。

1. 画异常分类和状态机：待处理、执行中、待确认、成功、部分成功、失败、取消。
2. 工具先只读。定义参数 schema、鉴权、组织与字段权限；用户自填 org_id 不可替代认证身份。
3. 模型可以提议工具调用，服务端独立验证权限、订单状态、金额、数量、单位和确认。
4. 写操作配置持久幂等记录、事务边界、回执、重试上限和补偿。内存 Map 只用于演示，不满足多进程生产要求。
5. 加入提示注入、假收件人、越权、重复、超时、数据冲突和取消测试。设最大步骤、时间、金额与调用预算。
6. 对照固定工作流与 Agent，测端到端成功率、危险动作阻断、P95、人审量和成本。自治若没有收益就保留简单方案。
7. 影子运行、有限灰度、工具熔断、人工接管、审计与事故演练都需在上线前验证。

验收产物：状态机、权限矩阵、接口契约、评测与红队样例、成功率与成本报告、灰度和回滚清单、真实用户反馈。
